How it works

The pipeline is deterministic-first: static analysis gathers the evidence, and LLMs are only allowed to judge what they can actually see. Every LLM step has a deterministic fallback.

01

Scan & profile

Inventory source files, map MCP capabilities and trust boundaries.

02

Extract features

AST + regex find shell calls, file access, network requests — no LLM guessing.

03

5 risk agents

Prompt injection, command exec, file access, SSRF, lifecycle.

LLM: semantic judgment
04

Blind review

Low-confidence findings get an independent second opinion — the reviewer never sees the agent's score.

LLM: second opinion
05

RAG + report

Accepted findings retrieve CWE/OWASP references; report renders with evidence chains.

LLM: summary

Purple stages use a language model, each grounded in real code and each with a deterministic fallback when no key is configured.

Measured against 16 labeled cases with ground truth: 8 real vulnerabilities (one per risk class) and 8 negative controls — including 7 hard negatives: code that looks dangerous to pattern-matching but is actually guarded.

  • The LLM-backed prompt-injection agent cleared its false positives with zero recall loss — all three of its hard negatives pass while the true injection is still caught.
  • Remaining false alarms come from agents that scored their mistakes confidently (≥ 0.7), bypassing the evaluator's blind-review gate.
  • LLM integration helps exactly where the evidence lives in the code window — leak-type judgments that need outside context remain hard.

Design principles

Evidence first

A finding without a verbatim code snippet is rejected. The reporter can only phrase facts that the pipeline already established — it cannot invent findings or numbers.

Blind second opinions

The LLM reviewer re-reads the source without seeing the agent's score or reasoning, so its judgment is independent — divergence between the two is a measurable signal.

Deterministic fallback

Every LLM call can fail or run keyless; the pipeline always completes on AST + regex + templates alone.

Traceable advice

Remediation references are retrieved from a curated CWE / OWASP knowledge base per finding — not recalled from model memory.
